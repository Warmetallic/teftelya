# Этап 2. Мета-слой: магазин апгрейдов, щадящий старт, злой множитель — дизайн

Дата: 2026-09-23. Статус: согласован с владельцем по секциям, ждёт плана реализации.
Опирается на этап 1 (`docs/specs/2026-09-10-foundation-sdk-design.md`): модули `src/*.js`, `expose()`, `YG`, `save.js`, экраны.

## 1. Цель и рамки

Дать игроку причину возвращаться: монеты покупают ощутимые апгрейды, первая покупка случается на 2–3 забеге,
пять покупок растягиваются на 3–4 сессии. Заодно закрыть три открытых вопроса README: щадящий старт,
пятый заряд как апгрейд, злость множителя. И сменить схему сохранений так, чтобы покупки не откатывались
при расхождении облака и локали.

Вне рамок: этажи башни, косметика, имя и реплики (этап 3), покупки за деньги, лидерборд, вертикальные полосы на
высоких телефонах (открытый вопрос владельца).

## 2. Решения владельца (2026-09-23)

| Вопрос | Решение | Почему |
|---|---|---|
| Щадящий старт | Мусор появляется по высоте и по одному виду; старт с массы 1 | Обучение через игру, история роста сохраняется |
| Заряды | Продаются: 5-й дёшево, 6-й дорого; максимум 6 | Самая ощутимая первая покупка |
| Множитель | ×1.5 / ×2 / ×3 / ×4 с массы 4 / 7 / 10 / 14 | Жадность должна окупаться явно; инфляцию гасят цены |
| Каталог | Только Заряды (2 уровня) и Магнит (3 уровня) | Минимум для первой версии; стартовая масса, броня, +монеты отвергнуты |
| Экран | Отдельный экран, вход с титула и с результатов | Не перегружать результаты; монеты «горячие» сразу после забега |
| Сохранения | Монотонный журнал `earned`/`spent`, слияние по максимуму | Игрок никогда не теряет; часы и порядок записей не нужны |

## 3. Правила забега

### 3.1 Гейты спавна (`src/world.js`, `spawn()`)
Высота `h` в метрах (`-spawnedTo / 10`). Сейчас: `isTrash = h > 8 && rnd < trashP`. Становится:
- `h < 25`: только еда;
- `25 ≤ h < 60`: из мусора только `hair`;
- `60 ≤ h < 100`: `hair`, `dirt`;
- `h ≥ 100`: `hair`, `dirt`, `fly`.
`trashP = clamp(0.12 + h/5000, 0.12, 0.5)` не меняется. Реализация: `pick()` получает подмножество каталога
`TRASH` по высоте (`trashPoolFor(h)`), константы `TRASH_FROM = { hair: 25, dirt: 60, fly: 100 }`.

### 3.2 Множитель (`src/game.js`, `coinMult()`)
`COIN_MULT = [[14, 4], [10, 3], [7, 2], [4, 1.5]]` — первая подходящая ступень сверху вниз, иначе 1. HUD показывает как сейчас.
Флаг `big` у всплывающего текста считается по множителю до прироста массы (устраняет отложенную мелочь этапа 1).

### 3.3 Заряды (`src/upgrades.js`, `src/game.js`, `src/render.js`)
`MAXJ` (константа 4) заменяется функцией `maxJumps() = JUMPS_BASE + upLevel('jumps')`, `JUMPS_BASE = 4`, уровни 0–2 → 4–6.
Используется в `reset()`, `eat()` (наполнение до максимума), `continueRun()`, регенерации в `updateRun()`, в HUD
(рисуется `maxJumps()` иконок, центрирование по их числу).

### 3.4 Магнит (`src/game.js`, `updateRun()`)
`magnetRadius()` = 0 / 60 / 90 / 120 px по уровню 0–3. Если > 0: для каждого живого предмета с `!it.trash`
на расстоянии `d < ball.r + magnetRadius()` от центра тефтели предмет сдвигается к центру на `min(d, MAGNET_SPEED * dt)`,
`MAGNET_SPEED = 300`. Движущаяся муха не еда, не притягивается. Никаких колец и подсветки. Столкновение и поедание — как сейчас.

### 3.5 Банк монет
`die()` и `doubleCoins()` вместо `save.coins += …` пишут `save.earned += …` (та же арифметика с `bankedCoins`).
Экран результатов и магазин показывают `coins()`.

## 4. Экономика

Каталог и цены (`src/upgrades.js`):
```
UPGRADES = {
  jumps:  { levels: [ { price: 80,  value: 5 }, { price: 300, value: 6 } ] },   // maxJumps
  magnet: { levels: [ { price: 60,  value: 60 }, { price: 180, value: 90 }, { price: 400, value: 120 } ] }, // радиус
}
```
Порядок покупок по цене: магнит 1 (60) → заряд 5 (80) → магнит 2 (180) → заряд 6 (300) → магнит 3 (400); сумма 1020.
Оценка дохода: ранний забег 15–50 монет, с множителем и «×2» до 60–80; первая покупка на 2–3 забеге, всё за 25–30 забегов.
Цены живут только в `UPGRADES` и правятся по метрикам после релиза.

## 5. Экран магазина и навигация

### 5.1 Состояние
Новое состояние `shop` в `game.js` (`state` принимает `'title' | 'play' | 'dead' | 'shop'`), `shopReturn: 'title' | 'dead'`
в `main.js`. Вход: `openShop(from)`; выход: `closeShop()` → `state = shopReturn`. Магазин — меню: `GameplayAPI` не трогаем
(из `dead` стоп уже отправлен, из `title` старт ещё не отправлен). Пауза в магазине: оверлей «Пауза» как на результатах,
`awaitTap` не ставится. Реклама из магазина не показывается.

### 5.2 Кнопки входа (`src/screens.js`)
- Титул: кнопка `shop` 220×52 по центру на `H * 0.62` (между подсказками и «Тапни, чтобы прыгнуть», который сдвигается на `H * 0.74`).
  Тап по кнопке → магазин; тап вне кнопки → старт, как сейчас.
- Результаты: четвёртая кнопка `shop` после `again` (тот же шаг 76 px). При трёх кнопках перед ней нижняя кнопка
  оказывается на `H * 0.56 + 228 = 706` px, помещается.
- Цвет кнопки `shop`: нейтральный `#ece6da` с тёмным текстом (`ad = false`, новый параметр `style: 'neutral'`).
- Точка-бейдж (кружок 10 px `#e3342f` у правого верхнего угла кнопки), если `canBuyAny()`.

### 5.3 Экран (`shopScreen()`)
- Затемнение 0.85, заголовок `T('shop')` на `H * 0.14`, баланс `● coins()` справа сверху (как HUD монет).
- Две карточки 400×150 на `H * 0.27` и `H * 0.50`: заголовок (`T('up.jumps')` / `T('up.magnet')`), строка эффекта
  `T('up.jumps.effect')`: «Прыжков: 4 → 5» (на максимуме «Прыжков: 6»), для магнита «Радиус: нет → 60»;
  индикатор уровней: точки `●` заполненные и `○` пустые по числу уровней; кнопка `buy:<id>` 200×48 справа внизу карточки:
  `T('buy') + ' ' + price` жёлтая, если `canBuy(id)`, серая (alpha 0.5) если не хватает, `T('max')` серая на максимуме.
- Кнопка `back` 220×52 на `H * 0.80`.
- Клавиатура: `Escape`, `Space`, `Enter` → назад. Стрелки в магазине ничего не делают.

### 5.4 Покупка (`buy(id)`)
Условия: уровень не максимальный и `coins() >= price`. Действие: `save.spent += price; save.up[id]++; persist(); sfx.buy();`
короткая подсветка рамки купленной карточки на 0.3 с (`shopFlash = { id, t }` в `screens.js`, гаснет по `dt`). Возвращает `true/false`.
Двойной тап не покупает дважды (проверка условий каждый раз, `persist()` пишет дедупликацией).

## 6. Сохранения v2 (`src/save.js`)

Схема: `{ v: 2, best, earned, spent, up: { jumps: 0..2, magnet: 0..3 } }`. `SAVE_VERSION = 2`.
- `coins()` = `max(0, earned - spent)`; экспортируется и используется всеми экранами вместо `save.coins`.
- `migrate(obj)`: любая версия → v2. Для v1 (или объекта с `coins` и без `earned`): `earned = coins, spent = 0, up = {0,0}`.
  Уровни зажимаются в допустимые диапазоны, всё приводится к целым ≥ 0.
- `mergeSaves(a, b)`: максимум по `best`, `earned`, `spent`, `up.jumps`, `up.magnet`. Корректность: все поля монотонны;
  `spent ≤ earned` на каждом устройстве, значит `max(earned) − max(spent) ≥ 0`, игрок может получить чуть больше, никогда меньше.
- `sameSave` сравнивает все поля включая `up`. `persist()` пишет `{ v, best, earned, spent, up }`.
- Совместимость: старое облако v1 читается один раз и перезаписывается v2 при первом `persist()`/`loadSave()`.
